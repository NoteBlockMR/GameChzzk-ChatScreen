# OBS Lua 채팅 수신 확장 (실험 버전)

**Python 수신기 없이 OBS 내부 Lua가 직접 치지직 채팅을 받습니다.** LuaJIT FFI로 OBS에 포함된 libcurl의 HTTPS/WebSocket 기능을 사용합니다. 메시지 표시만 OBS 브라우저 소스(HTML/JavaScript)가 담당합니다. 기존 독립 실행형 앱/1.1.7 릴리즈는 변경하지 않았습니다.

## 실행

1. `obs-plugin` 폴더 전체를 보관하세요. `chzzk-chat.lua`와 `chzzk_receiver.lua`, `chzzk_transport.lua`, `chzzk_http.lua`, `chzzk_json.lua`, `chzzk_fonts.lua`, `chzzk_overlay.lua`, `overlay.html`이 함께 필요합니다.
2. 이전 Python 수신기를 종료합니다. **start-helper.cmd는 실행하지 않습니다.** bridge.py/start-helper.cmd는 저장소의 이전 방식 참고 파일이며 Lua 전용 배포 ZIP에는 포함하지 않습니다.
3. OBS의 **도구 → 스크립트**에서 `chzzk-chat.lua`를 추가하거나 다시 불러옵니다.
4. 채널 주소/ID를 입력하고 **채팅 폰트** 목록에서 설치된 폰트를 선택합니다. 글자 크기와 채팅 폭·높이도 설정합니다. 새 폰트를 설치했다면 **설치된 폰트 목록 새로고침**을 누르세요.
5. **현재 장면에 채팅 추가 / 설정 적용**을 누릅니다. 기존 브라우저 소스도 새 Lua 수신 주소로 갱신됩니다.

수신은 비로그인 읽기 전용입니다. 로그인·채팅 전송은 지원하지 않으며 로그인/연령 인증이 필요한 채널은 지원하지 않을 수 있습니다. 한 번에 한 채널만 연결합니다.

## 구조 및 동작

- HTTPS로 채팅 채널과 읽기 토큰 조회 → WSS 연결 → 최근 채팅/실시간 채팅 수신을 Lua가 처리합니다.
- libcurl multi와 논블로킹 WebSocket, 30ms OBS 타이머를 사용합니다. 별도 Python/Node/PowerShell 프로세스를 띄우지 않습니다.
- TLS 인증서 검증을 유지합니다. 채팅 토큰을 파일이나 로그에 저장하지 않습니다.
- 브라우저 전달용 서버도 Lua가 운영하며 `127.0.0.1:18766`에만 바인딩합니다. 수신 메시지를 외부 서버로 전송하지 않습니다.
- 최근 100개 메시지, 제재/개별 삭제, 삭제 취소, 중복 방지, 핑 응답과 연결 실패 후 10→20→40→60초 간격 재시도를 지원합니다. 연결 오류 시 기존 메시지를 비웁니다.
- 스크립트 제거/OBS 종료 시 수신 연결과 로컬 서버가 종료됩니다. 게임 위 채팅은 아래 오버레이 기능을 사용할 수 있습니다.

## 지원 환경 및 확인 범위

Windows x64 OBS의 LuaJIT/FFI, WebSocket 지원 libcurl, 브라우저 소스가 필요합니다. 현재 설치 환경의 libcurl 8.12.1-DEV에서 검증했습니다. 다른 OBS 배포판이나 macOS/Linux는 검증하지 않았습니다.

실제 공개 채널에서 Lua로 연결 및 메시지 2개 수신을 확인했습니다. 제재/삭제/취소/중복/목록 제한 회귀 테스트, 로컬 HTTP/HTML 응답 및 Host 검사, 합성 장면 모의 테스트를 통과했습니다. 실제 OBS 장면의 최종 녹화 검증은 아직 필요합니다. 치지직 비공식 웹 채팅 프로토콜 변경 시 업데이트가 필요할 수 있습니다.

개발용 테스트 실행에만 Python을 사용하며, OBS 실행에는 필요하지 않습니다:

```powershell
.\.venv\Scripts\python.exe tests/run_obs_lua.py tests/obs_lua_receiver.lua
.\.venv\Scripts\python.exe tests/run_obs_lua.py tests/obs_compose.lua
```

JSON 파서는 [rxi/json.lua](https://github.com/rxi/json.lua)의 MIT 라이선스이며 `chzzk_json.lua`에 원문을 포함합니다. 통신 구현은 [libcurl multi](https://curl.se/libcurl/c/libcurl-multi.html)와 [WebSocket API](https://curl.se/libcurl/c/curl_ws_recv.html)를 사용합니다.

## 게임 + 채팅을 하나의 출력으로 구성

1. OBS에 **게임 캡처** 소스를 만들고 대상 게임을 지정합니다. 기존 윈도우/디스플레이 캡처도 선택할 수 있습니다.
2. 스크립트를 다시 로드하고 **캡처 소스 목록 새로고침**을 누릅니다.
3. **함께 출력할 캡처 소스**에서 원하는 소스를 선택하고 채널 주소와 채팅 폭을 지정합니다.
4. **게임 + 채팅 합성 장면 만들기 / 갱신**을 누릅니다.
5. OBS 장면 목록에서 **CHZZK 게임 + 채팅**을 선택합니다. 스튜디오 모드라면 미리보기 확인 후 전환하세요. 이 장면을 방송하거나 녹화하면 두 화면이 함께 출력됩니다.

게임은 왼쪽에 비율을 유지하여 배치하며, 채팅은 오른쪽에 표시합니다. 합성 장면의 높이는 OBS 기본 캔버스를 따릅니다. 채팅 폭은 캔버스의 절반 이하로 제한합니다. 기존 장면의 게임 배치는 바꾸지 않으며, 소스를 공유하므로 게임 캡처 속성 변경은 공유한 다른 장면에도 적용됩니다. 채팅 소스 역시 공유하므로 폭·높이 갱신이 다른 장면의 같은 채팅 소스에도 반영됩니다.

녹화 시작과 방송 장면 전환은 자동으로 하지 않습니다. 소리는 OBS 오디오 믹서에서 별도로 확인하세요. 별도 미리보기 창이 필요하면 합성 장면의 창 프로젝터를 열 수 있습니다.

합성 로직은 OBS LuaJIT에서 API 모의 객체로 검사했습니다(1920×1080/1280×720 배치, 반복 갱신, 캡처 변경, 폭 제한, 없는 소스 처리). 실제 OBS의 캡처·녹화 검증은 아직 필요합니다.

## WebSocket send 55가 반복될 때

전송 오류가 발생하면 해당 연결을 닫고 지연 후 재접속합니다. 같은 오류는 60초마다 최대 한 번 기록합니다. Lua 모듈 캐시도 새로고침 때 갱신하도록 처리했습니다. OBS에서 스크립트를 새로고침한 후 설정 적용을 다시 누르세요. 오류가 계속되면 네트워크/치지직 접속 상태도 확인해야 합니다.

OBS는 전역 `error()`를 예외가 아닌 로그 출력 함수로 교체합니다. 통신/HTTP/JSON 모듈은 자체 예외 함수를 사용하여 실패 시 실행을 중단하고 재연결 처리로 넘깁니다. `tests/obs_error_hook.lua`는 이 OBS 동작을 재현하고, 전송 오류 55 이후 500회 타이머 호출에서 추가 전송/원시 오류 로그가 없음을 검사합니다.

`schannel: timed out sending data (bytes sent: 0)` 대응: HTTPS/WebSocket 연결 단계의 15초 전체 제한을 WebSocket 연결 완료 직후 해제합니다. 이후 세션에는 채팅 응답 70초 감시와 재연결 처리를 적용합니다. HTTP API 조회와 초기 연결에는 기존 제한을 유지합니다.

## 게임 위 전용 채팅 오버레이 · Ctrl+Alt+F8

1. OBS 스크립트를 새로고침하고 채널 설정을 적용합니다.
2. **게임 위 채팅 열기 · 이동/크기 편집**을 누릅니다. 채팅 소스만 표시하는 OBS 창 프로젝터가 열립니다.
3. 창을 원하는 위치로 이동하고 크기를 조절합니다.
4. **Ctrl+Alt+F8**을 누르면 테두리가 숨겨지고 마우스 클릭이 뒤의 게임으로 통과합니다. 다시 누르면 편집 모드로 돌아갑니다. 창이 없을 때 누르면 게임 모드로 엽니다.
5. **게임 위 채팅 숨기기 / 표시** 버튼으로 게임용 창만 숨길 수 있습니다. 방송/녹화 채팅 소스는 계속 표시됩니다.

Windows의 창 모드/테두리 없는 게임용입니다. 독점 전체 화면 위 표시는 보장하지 않습니다. 프로젝터는 항상 위에 표시하며, **게임 위 채팅 불투명도** 설정은 모드 전환 때 적용됩니다. 창 전체의 불투명도를 조절하는 방식이며 배경을 픽셀 단위로 완전히 투명하게 만드는 방식은 아닙니다.

OBS **설정 → 단축키 → CHZZK 게임 위 채팅 · 클릭 통과 전환**에서 키를 변경할 수 있습니다. 기본값은 Ctrl+Alt+F8이며 변경한 바인딩도 저장합니다. 별도 Python 수신기나 독립 실행형 앱은 실행하지 않아도 됩니다.

스크립트 해제 시 오버레이 창 속성을 원래대로 복구합니다. 이 기능으로 새로 만든 OBS 프로젝터 창만 제어합니다. 실제 Windows 창에서 클릭 통과·테두리 제거·표시/숨김·속성 복구를 검사했으며, 실제 게임 위 OBS 프로젝터의 렌더링과 단축키 동작은 현장 확인이 필요합니다.
